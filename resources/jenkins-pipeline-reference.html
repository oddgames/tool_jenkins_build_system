Declarative Pipeline

Declarative Pipeline provides a simplified, opinionated syntax with the pipeline { } block. It enforces structure: no semicolons as statement separators, statements on individual lines, blocks containing only sections, directives, steps, or assignments.

pipeline {
    agent any
    stages {
        stage('Build') {
            steps {
                echo 'Building...'
            }
        }
        stage('Test') {
            steps {
                echo 'Testing...'
            }
        }
        stage('Deploy') {
            steps {
                echo 'Deploying...'
            }
        }
    }
}

agent

Specifies where the pipeline or stage executes. Required at the top level; optional within stages.

agent any

Execute on any available agent.

agent none

No global agent; each stage must declare its own. Useful for multi-platform builds.

agent { label 'labelName' }

Execute on an agent matching the label expression. Supports operators: && (AND), || (OR), ! (NOT), -> (implies), <-> (iff).

agent { label 'windows && unity' }

agent { node { label 'labelName' customWorkspace '/path' } }

Like label but with additional options such as customWorkspace.

agent { docker { image 'node:18' } }

Execute inside a Docker container.

agent {
    docker {
        image 'maven:3.9-eclipse-temurin-17'
        label 'docker'
        args '-v /tmp:/tmp'
    }
}

agent { dockerfile true }

Build and use a container from a Dockerfile in the repository.

post

Defines actions to run after pipeline or stage completion. Each condition block runs only if the condition is met.

ConditionWhen it runs
alwaysAlways, regardless of status
successOnly if current status is SUCCESS
failureOnly if current status is FAILURE
unstableOnly if current status is UNSTABLE (e.g. test failures)
changedOnly if status differs from previous build
fixedPrevious run was unsuccessful, current is SUCCESS
regressionPrevious run was SUCCESS, current is worse
abortedBuild was manually aborted
cleanupRuns after all other post conditions
pipeline {
    agent any
    stages {
        stage('Test') {
            steps { sh 'make check' }
        }
    }
    post {
        always {
            junit '**/target/*.xml'
        }
        failure {
            mail to: 'team@example.com',
                 subject: "FAILED: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                 body: "Check: ${env.BUILD_URL}"
        }
    }
}
Post actions in declarative pipelines run after node release if the build fails early. Ensure critical cleanup runs within the stage or use always blocks.

stages / stage

stages contains a sequence of stage directives. Each stage must have a unique name and a steps, stages (sequential), parallel, or matrix block.

Sequential Stages

stage('Parent') {
    stages {
        stage('First') { steps { echo 'first' } }
        stage('Second') { steps { echo 'second' } }
    }
}

Parallel Stages

stage('Tests') {
    failFast true
    parallel {
        stage('Unit') { steps { sh 'make unit' } }
        stage('Integration') { steps { sh 'make integration' } }
    }
}

environment

Defines key-value pairs as environment variables. Can be top-level (all stages) or stage-level (scoped).

pipeline {
    agent any
    environment {
        CC = 'clang'
        DEPLOY_TO = 'production'
    }
    stages {
        stage('Build') {
            environment {
                DEBUG_FLAGS = '-g'
            }
            steps {
                sh 'printenv'
            }
        }
    }
}

Dynamic Variables

environment {
    GIT_COMMIT_SHORT = sh(returnStdout: true, script: 'git rev-parse --short HEAD').trim()
}

credentials() helper

environment {
    AWS_ACCESS_KEY_ID     = credentials('aws-key-id')
    AWS_SECRET_ACCESS_KEY = credentials('aws-secret-key')
    // For username/password: creates _USR and _PSW variants
    DOCKER_CREDS = credentials('docker-hub-creds')
    // DOCKER_CREDS = username:password
    // DOCKER_CREDS_USR = username
    // DOCKER_CREDS_PSW = password
}

options

Pipeline-wide configuration. Applied at the top level or per-stage.

OptionDescription
buildDiscarder(logRotator(...))Manage build log retention
disableConcurrentBuilds()Prevent parallel executions of this pipeline
disableResume()Do not allow resume after controller restart
timeout(time: 1, unit: 'HOURS')Global timeout for entire pipeline
retry(3)Retry entire pipeline on failure
timestamps()Prepend timestamps to console output
skipDefaultCheckout()Do not auto-checkout SCM in agent
skipStagesAfterUnstable()Skip remaining stages if build becomes unstable
preserveStashes(buildCount: 5)Preserve stashes from completed builds for replay
ansiColor('xterm')Enable ANSI color in console
options {
    buildDiscarder(logRotator(numToKeepStr: '10'))
    timeout(time: 1, unit: 'HOURS')
    timestamps()
    disableConcurrentBuilds()
}

parameters

User-provided inputs for the pipeline. Available on second run onwards (first run defines them). Access via params.NAME.

TypeSyntax
stringstring(name: 'DEPLOY_ENV', defaultValue: 'staging', description: '...')
texttext(name: 'CONFIG', defaultValue: '', description: '...')
booleanParambooleanParam(name: 'SKIP_TESTS', defaultValue: false, description: '...')
choicechoice(name: 'PLATFORM', choices: ['steam', 'ios', 'android'], description: '...')
passwordpassword(name: 'SECRET', defaultValue: '', description: '...')
pipeline {
    agent any
    parameters {
        string(name: 'BRANCH', defaultValue: 'main', description: 'Branch to build')
        booleanParam(name: 'DEPLOY', defaultValue: false, description: 'Deploy after build?')
        choice(name: 'ENVIRONMENT', choices: ['dev', 'staging', 'prod'], description: 'Target')
    }
    stages {
        stage('Example') {
            steps {
                echo "Building ${params.BRANCH} for ${params.ENVIRONMENT}"
            }
        }
    }
}

triggers

Automated pipeline re-execution.

TriggerDescription
cron('H */4 * * 1-5')Cron schedule (H = hash for load distribution)
pollSCM('H */5 * * *')Poll SCM for changes on schedule
upstream(upstreamProjects: 'job1,job2', threshold: hudson.model.Result.SUCCESS)Trigger when upstream jobs complete
triggers {
    pollSCM('H/5 * * * *')
}

when

Conditional stage execution. Evaluated before the stage's agent by default; use beforeAgent true to control this.

ConditionExample
branchwhen { branch 'main' }
branch (pattern)when { branch pattern: 'release-*', comparator: 'GLOB' }
environmentwhen { environment name: 'DEPLOY', value: 'true' }
expressionwhen { expression { return params.DEPLOY } }
notwhen { not { branch 'main' } }
allOfwhen { allOf { branch 'main'; environment name: 'DEPLOY', value: 'true' } }
anyOfwhen { anyOf { branch 'main'; branch 'staging' } }
tagwhen { tag 'v*' }
changelogwhen { changelog '.*\\[ci\\].*' }
changesetwhen { changeset '**/*.js' }
triggeredBywhen { triggeredBy 'TimerTrigger' }
beforeAgentwhen { beforeAgent true; branch 'main' }
beforeInputwhen { beforeInput true; branch 'main' }
beforeOptionswhen { beforeOptions true; branch 'main' }
stage('Deploy') {
    when {
        allOf {
            branch 'main'
            expression { return params.DEPLOY == true }
        }
    }
    steps {
        sh './deploy.sh'
    }
}

matrix

Multi-dimensional parallel execution. Define axes and optionally exclude combinations.

stage('Test') {
    matrix {
        axes {
            axis {
                name 'PLATFORM'
                values 'linux', 'windows', 'mac'
            }
            axis {
                name 'JAVA'
                values '11', '17', '21'
            }
        }
        excludes {
            exclude {
                axis { name 'PLATFORM'; values 'mac' }
                axis { name 'JAVA'; values '11' }
            }
        }
        stages {
            stage('Build & Test') {
                steps {
                    echo "Testing on ${PLATFORM} with Java ${JAVA}"
                }
            }
        }
    }
}

Scripted Pipeline

Uses Groovy as its foundation, offering flexibility through general-purpose constructs. Wrapped in node { } blocks.

node('unity') {
    stage('Build') {
        checkout scm
        sh 'make'
    }
    stage('Test') {
        try {
            sh 'make check'
        } catch (e) {
            currentBuild.result = 'UNSTABLE'
            throw e
        } finally {
            junit '**/target/*.xml'
        }
    }
}

Use the script { } step as an escape hatch in Declarative Pipelines for complex Groovy logic.

steps {
    script {
        def browsers = ['chrome', 'firefox']
        for (b in browsers) {
            echo "Testing on ${b}"
        }
    }
}

node / dir / ws

node

Allocates an executor on an agent. Label expressions filter which agents can run.

node('windows && unity') {
    // runs on a Windows agent with the 'unity' label
}

node {
    // runs on any available agent
}

dir

Changes working directory for enclosed steps. Relative to current workspace.

dir('subdir') {
    sh 'ls -la'
}

ws

Custom workspace allocation. Automatic suffix (@2) if same path used concurrently.

ws('/opt/build/custom-workspace') {
    sh 'make'
}

sh / bat / powershell / pwsh

Execute scripts on agents. All share common optional parameters.

ParameterTypeDescription
scriptStringThe script to execute (required)
returnStatusbooleanReturn exit code instead of failing on non-zero
returnStdoutbooleanReturn stdout as String (use .trim()!)
encodingStringOutput encoding (e.g. 'UTF-8')
labelStringLabel for Blue Ocean display

sh (Unix/Linux/macOS)

// Simple
sh 'echo hello'

// Multi-line
sh '''
    echo "Building..."
    make clean
    make all
'''

// Capture output
def version = sh(returnStdout: true, script: 'cat VERSION').trim()

// Check exit code
def status = sh(returnStatus: true, script: 'make test')
if (status != 0) {
    echo "Tests failed with status ${status}"
}

bat (Windows Batch)

bat 'echo Building on Windows'
bat 'msbuild /p:Configuration=Release'

// Multi-line
bat '''
    echo off
    set UNITY_PATH=C:\\UnityEditors\\2022.3.0f1
    "%UNITY_PATH%\\Editor\\Unity.exe" -quit -batchmode
'''

powershell (Windows PowerShell 3+)

powershell 'Get-ChildItem -Recurse'
powershell returnStdout: true, script: '$PSVersionTable.PSVersion'

pwsh (PowerShell Core 6+, cross-platform)

pwsh 'Write-Output "Hello from PowerShell Core"'
returnStdout includes a trailing newline. Always use .trim() on the result.

echo / print

Print a message to the build console log.

echo 'Hello, World!'
echo "Build number: ${env.BUILD_NUMBER}"

catchError / error / retry / timeout / waitUntil / warnError

catchError

Catch an error, set build/stage result, but continue the pipeline.

catchError(buildResult: 'UNSTABLE', stageResult: 'FAILURE') {
    sh 'make test'
}
// Pipeline continues even if 'make test' fails
ParameterTypeDescription
buildResultStringResult to set: SUCCESS, UNSTABLE, FAILURE, NOT_BUILT, ABORTED
stageResultStringStage result to set
catchInterruptionsbooleanCatch build interruptions (abort). Default: true
messageStringMessage to print if error is caught

error

Signal an error, stopping the current stage/pipeline.

error 'Deployment target not specified!'

retry

Repeat the block up to N times if it fails.

retry(3) {
    sh 'curl -f https://example.com/api/health'
}

timeout

Abort the block if it exceeds the time limit.

timeout(time: 30, unit: 'MINUTES') {
    sh 'make build'
}

// With activity flag — resets timer on each log output
timeout(time: 5, unit: 'MINUTES', activity: true) {
    sh 'long-running-command'
}
ParameterTypeDescription
timeintTimeout duration
unitStringNANOSECONDS, MICROSECONDS, MILLISECONDS, SECONDS, MINUTES, HOURS, DAYS
activitybooleanTimeout resets on console output activity

waitUntil

Repeatedly runs body until it returns true. Increases wait between retries.

waitUntil {
    def status = sh(returnStatus: true, script: 'curl -sf http://localhost:8080/health')
    return status == 0
}

warnError

Like catchError but sets build to UNSTABLE on exception.

warnError('Lint check had issues') {
    sh 'npm run lint'
}

readFile / writeFile / fileExists / deleteDir

readFile

Read a file from the workspace as a String.

def content = readFile(file: 'config.json', encoding: 'UTF-8')
// Short form:
def content = readFile 'config.json'

writeFile

Write text content to a file in the workspace.

writeFile(file: 'output.txt', text: 'Hello World', encoding: 'UTF-8')

fileExists

Check if a file exists in the workspace. Returns boolean.

if (fileExists('Dockerfile')) {
    echo 'Found Dockerfile'
}

deleteDir

Recursively delete the current directory. Typically used for workspace cleanup.

dir('build-output') {
    deleteDir()
}

stash / unstash

Save and restore files between stages, even across different nodes.

stash

stash(name: 'app-jar', includes: '**/target/*.jar', excludes: '**/test-*')
// Short form for name only:
stash name: 'source', includes: '**/*'
ParameterTypeDescription
nameStringUnique name for this stash (required)
includesStringAnt-style include pattern
excludesStringAnt-style exclude pattern
allowEmptybooleanAllow stashing zero files (default: false)
useDefaultExcludesbooleanUse default Ant excludes (default: true)

unstash

unstash 'app-jar'
Stashed files are deleted after the pipeline completes. For persistent artifacts, use archiveArtifacts.

archiveArtifacts

Archive build outputs on the Jenkins controller for download.

archiveArtifacts artifacts: '**/build/*.apk', fingerprint: true

// Allow archiving even if no files match
archiveArtifacts artifacts: '**/*.log', allowEmptyArchive: true
ParameterTypeDescription
artifactsStringAnt-style file pattern (required)
fingerprintbooleanRecord fingerprints for tracking
allowEmptyArchivebooleanDon't fail if no matches (default: false)
excludesStringAnt-style exclude pattern
followSymlinksbooleanFollow symbolic links (default: true)
onlyIfSuccessfulbooleanArchive only on success (default: false)

sleep / unstable

sleep

Pause execution.

sleep 10           // 10 seconds
sleep time: 2, unit: 'MINUTES'

unstable

Set the stage result to UNSTABLE.

unstable(message: 'Test coverage below threshold')

isUnix

Returns true if the current agent is a Unix-like system. Must be called within a node context.

node {
    if (isUnix()) {
        sh 'make'
    } else {
        bat 'msbuild'
    }
}
Do not use System.getProperty('os.name') — this returns the Jenkins controller OS, not the agent OS. Always use isUnix().

build (Trigger Downstream Job)

Trigger another Jenkins job and optionally wait for its result.

// Simple trigger, wait for completion
build job: 'downstream-job'

// With parameters
build job: 'deploy',
      parameters: [
          string(name: 'ENVIRONMENT', value: 'production'),
          booleanParam(name: 'DRY_RUN', value: false)
      ]

// Don't propagate failure
build job: 'optional-job', propagate: false

// Fire and forget
build job: 'notification-job', wait: false

// Relative path (same folder)
build job: '../sibling-folder/other-job'

// Absolute path
build job: '/top-folder/nested-folder/job-name'
ParameterTypeDescription
jobStringJob name or path (required)
parametersListParameters to pass
propagatebooleanInherit downstream result (default: true)
waitbooleanWait for completion (default: true)
waitForStartbooleanWait only until started (default: false)
quietPeriodintSeconds to wait before building

input

Pause pipeline and wait for user interaction. Provides proceed/abort buttons with optional parameter collection.

// Simple approval gate
input message: 'Deploy to production?', ok: 'Deploy'

// With parameters — single param returns its value directly
def version = input(
    message: 'Select version',
    parameters: [
        choice(name: 'VERSION', choices: ['1.0', '2.0', '3.0'], description: 'Release version')
    ]
)

// Multiple params return a map
def userInput = input(
    message: 'Configure deployment',
    parameters: [
        string(name: 'TAG', defaultValue: 'latest', description: 'Docker tag'),
        booleanParam(name: 'NOTIFY', defaultValue: true, description: 'Send notification')
    ]
)
echo "Tag: ${userInput.TAG}, Notify: ${userInput.NOTIFY}"
ParameterTypeDescription
messageStringPrompt message (required)
okStringCustom proceed button text
cancelStringCustom abort button text
idStringUnique ID for external responses
parametersListParameters to collect
submitterStringComma-separated user IDs/group names allowed to submit
submitterParameterStringEnv var name to store who submitted
Tip: Wrap input outside of node blocks to avoid holding an executor while waiting for approval.

parallel

Execute branches concurrently. In Declarative, use the parallel directive within a stage. In Scripted, use the parallel step.

Declarative

stage('Test') {
    failFast true
    parallel {
        stage('Unit Tests') {
            agent { label 'linux' }
            steps { sh 'make unit-test' }
        }
        stage('Integration Tests') {
            agent { label 'linux' }
            steps { sh 'make integration-test' }
        }
    }
}

Scripted

parallel(
    linux: {
        node('linux') { sh 'make test' }
    },
    windows: {
        node('windows') { bat 'make test' }
    },
    failFast: true
)

load

Evaluate a Groovy source file from the workspace.

def pipeline = load 'pipeline.groovy'
pipeline.functionA()

// pipeline.groovy typically ends with:
// return this

credentials() Helper

Used within the environment directive in Declarative Pipeline to bind credentials to env vars.

Secret Text

environment {
    API_TOKEN = credentials('my-api-token')
    // API_TOKEN contains the secret string
}

Username + Password

environment {
    CREDS = credentials('my-user-pass')
    // CREDS     = "username:password"
    // CREDS_USR = "username"
    // CREDS_PSW = "password"
}

Secret File

environment {
    KUBECONFIG = credentials('my-kubeconfig')
    // KUBECONFIG = path to temporary file containing the secret
}

withCredentials

Bind credentials to variables within a scoped block. Works in both Declarative and Scripted pipelines. Secrets are masked in console output.

// Username and password
withCredentials([usernamePassword(
    credentialsId: 'docker-hub',
    usernameVariable: 'DOCKER_USER',
    passwordVariable: 'DOCKER_PASS'
)]) {
    sh 'docker login -u $DOCKER_USER -p $DOCKER_PASS'
}

// Secret text
withCredentials([string(credentialsId: 'api-key', variable: 'API_KEY')]) {
    sh 'curl -H "Authorization: Bearer $API_KEY" https://api.example.com'
}

// Secret file
withCredentials([file(credentialsId: 'gcloud-key', variable: 'GCLOUD_KEY_FILE')]) {
    sh 'gcloud auth activate-service-account --key-file=$GCLOUD_KEY_FILE'
}

// SSH key
withCredentials([sshUserPrivateKey(
    credentialsId: 'deploy-key',
    keyFileVariable: 'SSH_KEY',
    usernameVariable: 'SSH_USER'
)]) {
    sh 'ssh -i $SSH_KEY $SSH_USER@server.example.com "deploy.sh"'
}

// Multiple bindings
withCredentials([
    string(credentialsId: 'slack-token', variable: 'SLACK_TOKEN'),
    usernamePassword(credentialsId: 'nexus', usernameVariable: 'NEXUS_USER', passwordVariable: 'NEXUS_PASS')
]) {
    sh 'upload-artifact.sh'
}

// AWS credentials
withCredentials([aws(credentialsId: 'aws-creds',
                     accessKeyVariable: 'AWS_ACCESS_KEY_ID',
                     secretKeyVariable: 'AWS_SECRET_ACCESS_KEY')]) {
    sh 'aws s3 ls'
}

Supported Binding Types

TypeParameters
stringcredentialsId, variable
usernamePasswordcredentialsId, usernameVariable, passwordVariable
usernameColonPasswordcredentialsId, variable
sshUserPrivateKeycredentialsId, keyFileVariable, usernameVariable, passphraseVariable
filecredentialsId, variable
certificatecredentialsId, keystoreVariable, passwordVariable, aliasVariable
awscredentialsId, accessKeyVariable, secretKeyVariable
dockerCertcredentialsId, variable
gitUsernamePasswordcredentialsId, gitToolName
Security: Use single quotes in sh steps to prevent Groovy interpolation of secrets. Double-quoted strings expose secrets in process arguments.

findFiles

Locate files in the workspace using Ant-style glob patterns.

def files = findFiles(glob: '**/*.apk')
echo "Found ${files.length} APKs"
for (f in files) {
    echo "${f.name} — ${f.path} — ${f.length} bytes"
}

// With excludes
def files = findFiles(glob: '**/*.jar', excludes: '**/test-*.jar')

Returns an array of FileWrapper objects with properties: name, path, directory (boolean), length, lastModified.

Calculate file checksums.

def hash = sha256(file: 'artifact.zip')

touch

touch file: 'timestamp.txt'

tee

tee('build.log') {

pwd

checkout

Check out source code from version control. Supports Git, SVN, and many other SCMs.

// Checkout the SCM configured in the job
checkout scm

// Git checkout with specific config
checkout([
    $class: 'GitSCM',
    branches: [[name: '*/main']],
    userRemoteConfigs: [[
        url: 'https://github.com/org/repo.git',
        credentialsId: 'github-token'
    ]],
    extensions: [
        [$class: 'CloneOption', depth: 1, shallow: true],
        [$class: 'CleanBeforeCheckout']
    ]
])

git

Simplified Git checkout step.

git url: 'https://github.com/org/repo.git', branch: 'main'
git url: 'https://github.com/org/repo.git', credentialsId: 'my-creds', branch: 'develop'

slackSend / slackUploadFile

slackSend

Shared Library Structure

(root)
+- src/                          # Groovy source files (added to classpath)
|   +- org/
|       +- foo/
|           +- Bar.groovy        # for org.foo.Bar class
+- vars/                         # Global variables / custom steps
|   +- foo.groovy                # defines the 'foo' global variable
|   +- foo.txt                   # help documentation for 'foo'
+- resources/                    # Non-Groovy files (external libraries only)
|   +- org/
|       +- foo/
|           +- bar.json          # loaded via libraryResource step
  • src/ — Standard Java directory structure, compiled and added to classpath
  • vars/ — On-demand singletons; filenames become Pipeline variable names
  • resources/ — Static files loaded via libraryResource step

Loading Libraries

@Library annotation

// Load single library
@Library('my-shared-library') _

// Load specific version (branch, tag, commit)
@Library('my-shared-library@1.0') _
@Library('my-shared-library@main') _

// Load multiple libraries
@Library(['my-shared-library', 'otherlib@abc1234']) _

// Import classes from src/
@Library('somelib')
import com.mycorp.pipeline.somelib.UsefulClass
Do not import global variables from vars/. This forces the compiler to interpret fields and methods as static, causing confusing errors.

Dynamic loading (library step)

// Load at runtime
library 'my-shared-library'

// Specific version
library 'my-shared-library@main'

// Computed version
library "my-shared-library@${BRANCH_NAME}"

// Access src/ classes dynamically
library('my-shared-library').com.mycorp.pipeline.Utils.someStaticMethod()

// With explicit retriever (no preconfiguration needed)
library identifier: 'custom-lib@master', retriever: modernSCM([
    $class: 'GitSCMSource',
    remote: 'git@github.com:org/jenkins-utils.git',
    credentialsId: 'my-key'
])

Library Configuration

  • Global Trusted Libraries: Manage Jenkins → System → Global Trusted Pipeline Libraries. Run outside sandbox — full Jenkins API access.
  • Folder-level Libraries: Scoped to folder and subfolders. Always untrusted (sandboxed).
  • Implicit loading: Libraries marked "Load implicitly" are auto-loaded for all pipelines.

Testing Library PRs (GitHub)

@Library('my-shared-library@pull/123/head') _

Global Variables (vars/)

Scripts in vars/ are instantiated as on-demand singletons. Multiple methods in one file:

// vars/log.groovy
def info(message) {
    echo "INFO: ${message}"
}

def warning(message) {
    echo "WARNING: ${message}"
}

// Jenkinsfile usage:
log.info 'Starting'
log.warning 'Nothing to do!'

Custom Steps (call method)

// vars/sayHello.groovy
def call(String name = 'human') {
    echo "Hello, ${name}."
}

// Jenkinsfile:
sayHello 'Joe'
sayHello()  // uses default

Block-accepting Steps

// vars/windows.groovy
def call(Closure body) {
    node('windows') {
        body()
    }
}

// Jenkinsfile:
windows {
    bat 'cmd /?'
}

DSL-style Steps

// vars/buildPlugin.groovy
def call(Map config) {
    node {
        git url: "https://github.com/jenkinsci/${config.name}-plugin.git"
        sh 'mvn install'
        mail to: '...', subject: "${config.name} plugin build", body: '...'
    }
}

// Jenkinsfile:
buildPlugin name: 'git'
In Declarative Pipeline, method calls on library objects outside script { } blocks will fail (JENKINS-42360). Wrap in script { }.

Using @Field for Constants

// vars/myLib.groovy
@groovy.transform.Field
def MY_CONSTANT = "some-value"

def call() {
    echo MY_CONSTANT
}
Tip: Global variables should be stateless. State is lost on controller restart. Use static classes or local instantiation instead.

Classes (src/)

Library classes in src/ cannot directly call Pipeline steps. Two patterns:

Pattern 1: Script-style class (return this)

// src/org/foo/Zot.groovy
package org.foo

def checkOutFrom(repo) {
    git url: "git@github.com:jenkinsci/${repo}"
}

return this

// Usage:
def z = new org.foo.Zot()
z.checkOutFrom('my-repo')

Pattern 2: Pass steps explicitly

// src/org/foo/Utilities.groovy
package org.foo

class Utilities implements Serializable {
    def steps
    Utilities(steps) { this.steps = steps }

    def mvn(args) {
        steps.sh "${steps.tool 'Maven'}/bin/mvn -o ${args}"
    }
}

// Jenkinsfile:
@Library('utils') import org.foo.Utilities
def utils = new Utilities(this)
node {
    utils.mvn 'clean package'
}

Pattern 3: Static methods with script reference

// src/org/foo/Utilities.groovy
package org.foo

class Utilities {
    static def mvn(script, args) {
        script.sh "${script.tool 'Maven'}/bin/mvn -s ${script.env.HOME}/jenkins.xml -o ${args}"
    }
}

// Jenkinsfile:
@Library('utils') import static org.foo.Utilities.*
node {
    mvn this, 'clean package'
}
Classes storing state must implement Serializable for Pipeline suspension/resumption (CPS).

Library Resources

Load non-Groovy files from the resources/ directory of an external library.

def template = libraryResource 'com/mycorp/pipeline/somelib/request.json'
writeFile file: 'request.json', text: template

Files load as strings. Use unique package structures to avoid conflicts between libraries.

Writing Libraries — Tips

  • vars/*.groovy files get CPS-transformed like Pipeline scripts
  • Use @NonCPS annotation for methods that should not be CPS-transformed (e.g. data processing)
  • Avoid @Grab for third-party JARs — prefer standalone executables called via sh/bat
  • Use Replay to test library changes on untrusted libraries before committing
  • Global Variable Reference is populated only after a successful pipeline run using the library
  • Declarative Pipelines can be defined in vars/*.groovy call methods (since Declarative 1.2)

String Interpolation

Groovy single quotes prevent interpolation; double quotes enable it.

def name = 'World'
echo 'Hello ${name}'    // Output: Hello ${name}  (literal)
echo "Hello ${name}"    // Output: Hello World     (interpolated)
NEVER interpolate secrets in shell commands! 
// BAD — secret exposed in process arguments
sh "curl -H 'Authorization: Bearer ${API_TOKEN}' https://api.com"

// GOOD — shell expands the env var, not Groovy
sh 'curl -H "Authorization: Bearer ${API_TOKEN}" https://api.com'
Injection risk: User-controlled parameters in double-quoted shell commands can execute arbitrary code. 
// VULNERABLE — user can inject: hello; rm -rf /
sh "echo ${params.USER_INPUT}"

// SAFE — single quotes prevent Groovy interpolation
sh 'echo ${USER_INPUT}'

Security Best Practices

  • Use single quotes in sh/bat steps when referencing credentials
  • Place withCredentials outside dir() blocks for file credentials
  • Never expose secrets via echo — they're masked but can be captured
  • Untrusted pipelines should never access trusted credentials
  • Credential variables are scoped only within their withCredentials block
  • On Windows, bat 'echo %VAR%' is safer than bat "echo ${VAR}"
  • Special characters in credentials (%, &, etc.) can be mangled by interpolation

Failure Handling

Declarative — post section

post {
    always  { junit '**/target/*.xml' }
    failure { mail to: 'team@example.com', subject: 'Build Failed', body: '...' }
    success { echo 'All good!' }
    fixed   { slackSend color: 'good', message: 'Build is back to normal' }
}

Scripted — try/catch/finally

node {
    try {
        stage('Build') { sh 'make' }
        stage('Test')  { sh 'make test' }
    } catch (e) {
        currentBuild.result = 'FAILURE'
        mail to: 'team@example.com', subject: 'Build Failed', body: e.toString()
        throw e
    } finally {
        stage('Cleanup') { deleteDir() }
    }
}

Non-fatal errors

// Continue pipeline, mark as unstable
catchError(buildResult: 'UNSTABLE', stageResult: 'FAILURE') {
    sh 'make optional-check'
}

// Or set manually
currentBuild.result = 'UNSTABLE'

Multiple Agents

Use agent none at pipeline level, then specify agents per stage. Use stash/unstash to share files across agents.

pipeline {
    agent none
    stages {
        stage('Build') {
            agent { label 'linux' }
            steps {
                checkout scm
                sh 'make'
                stash includes: '**/target/*.jar', name: 'app'
            }
        }
        stage('Test on Linux') {
            agent { label 'linux' }
            steps {
                unstash 'app'
                sh 'make check'
            }
        }
        stage('Test on Windows') {
            agent { label 'windows' }
            steps {
                unstash 'app'
                bat 'make check'
            }
        }
    }
}
